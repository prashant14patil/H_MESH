# Stage 1 capture quality and HMR2 diagnostics

## Status

**Partial prototype, not a reliable capture-quality gate.** The single-photo HMR2 inference engine was not changed, no mesh fusion was implemented, and existing mesh outputs were not overwritten. Real-frame HMR2 parameter retention was explicitly authorized by the user for diagnostic use.

## Implementation

The additive capture-quality service (`backend/services/capture_quality.py`) combines existing extraction and pose metadata with full-frame and landmark-region Laplacian variance, ROI gradient, brightness and clipped-pixel fraction. `QualityConfig` controls screening thresholds; the existing extraction blur flag is preserved. Unreadable frames and explicit no-person results are rejected; other problems produce review warnings. The optional `reject_blurry` setting is separate from warning thresholds.

The opt-in background job (`backend/services/capture_quality_job.py`) uses OpenCV HOG detections as unvalidated evidence and writes a separate JSON report. The new `/api/capture-quality` router offers start, status and report endpoints. `CaptureQualityPanel.jsx` lets users request a report and inspect per-frame reasons and coverage counts. It does not modify the existing extraction workflow.

The existing pose processor tracks one pose, so person count is not known from its output. Its `detection_confidence` is mean tracked landmark visibility, not a calibrated person-detection confidence. HOG raw weights are not probabilities. Landmark box overlap and consecutive-frame IoU are tentative diagnostics, not a reliable identity tracker. Partial or occluded bystanders may be missed. Background interference and obstruction are currently recorded as unknown.

The existing viewpoint estimator's shoulder-width/nose-depth output is retained as an **unvalidated heuristic**, not a probability or reconstruction accuracy. Ambiguous front/back and ambiguous-side hints are represented as unknown in new reports. Physical yaw and complete 360-degree coverage are not established.

The automated report leaves identity and person count unverified. Stage 1.1 adds a manually selected reference box, unvalidated candidate suggestions and explicit per-frame confirm/reassign/reject decisions. Suggestions use box overlap and center distance, optionally anchored by an earlier human-reviewed frame; they never approve identity automatically. Human confirmation is not biometric verification.

The video-mesh gate now requires a matching report and review session, matching source and reference-frame hashes, explicit per-frame human decisions, the default screening policy and passed readability, person-presence, sharpness, lighting and full-body checks. It snapshots the reviewed subject box as a PNG crop and sends that crop to the unchanged single-photo inference engine. The reviewer must inspect and exclude overlapping people: HOG may miss bystanders, and a crop does not guarantee subject isolation. Old pose summaries lacking frame hashes require pose processing again. Previous ungated video-batch clients must be updated for the new request fields.

## HMR2 diagnostic export

`backend/services/hmr2_diagnostics.py` and `scripts/export_hmr2_diagnostics.py` provide an opt-in single-frame diagnostic path using an explicit user-supplied subject bounding box. It uses the existing `ViTDetDataset` and model forward pass without editing the production inference engine. It saves an exclusive output directory containing crop image, JSON metadata and non-pickle NPZ arrays for vertices, faces, betas, body pose, global orientation, crop camera predictions, focal length and image/crop affine transforms. Camera values are model predictions, not camera calibration; shape and pose are not validated measurements.

One authorized real-frame smoke test was saved to `outputs/hmr2_diagnostics/stage1_frame003_001/`. The manually selected padded box was `[420, 10, 770, 680]` in a 1280×720 image, derived from pose landmarks and visual review; identity is not verified. The source was flagged blurry. The saved arrays contained 6,890 vertices, 13,776 faces, 10 betas and 23 body-pose rotation matrices. All saved arrays were finite, face indices were in range, and the affine inverse round trip for three points had maximum error below 3e-13 pixels. This verifies serialization and affine inversion for one case only, not image-space reprojection consistency, anatomical accuracy, camera scale or multi-view readiness.

## Stage 1.2: HOG candidate suppression and browser validation

- The quality job still uses OpenCV HOG `detectMultiScale` with its existing settings. Its returned rectangles may already have undergone OpenCV grouping; “raw” below means **HOG-returned candidates**, not raw sliding-window hits. Scores are uncalibrated and not probabilities.
- A deterministic score-ordered IoU NMS diagnostic is recorded per frame in `detector_nms`. The fixed screening threshold is IoU **greater than 0.5**; ties retain the earlier candidate. The record includes raw and filtered counts, retained indices and boxes, suppressed-to-retained indices and IoUs, and invalid indices. Missing detector evidence produces unavailable diagnostics; invalid candidates make the displayed filtered count incomplete.
- `detector_evidence`, `person_count_observed`, multiple-person warnings, association suggestions and server crop validation continue to use the original HOG-returned candidates. NMS does not clear warnings, approve frames, change mandatory quality thresholds, establish identity or relax the server-side gate. Existing reports without NMS remain readable. A suppressed box can still represent a real overlapping person; a remaining box can be a duplicate or a false positive.
- **Saved-capture comparison:** report `2f1c901b-4979-4591-8687-fb611822a69e`, recording `5d661e4e-9689-4d5a-aac7-2572a2365c04`: all 30 extracted frame hashes matched the report. Applying NMS in memory to the saved candidates gave raw→filtered distributions: 0→0 on five frames, 1→1 on nine, 2→2 on nine, 3→3 on six and 3→2 on one. All 16 originally multi-candidate frames still have at least two retained candidates; existing warnings remain unchanged. No report was overwritten.
- **Frame 016:** the hash-matched image visibly contains one person. Its three HOG candidates cover head and overlapping torso regions. Their pairwise IoUs are 0, 0.267 and 0; NMS retains all three. This is evidence of partial/duplicate detections in that frame, and shows that IoU NMS does not solve nested low-IoU detections.
- **Frame 020:** the hash-matched image visibly contains one person. Two overlapping torso-region candidates have IoU 0.513; the lower-scored candidate is suppressed, leaving two of three candidates. The remaining separate candidate is not automatically classified as a person or discarded. Frame 005 has three retained candidates with pairwise IoUs 0.061, 0.039 and 0.014. **Troubleshooting—do not bypass gates:**

- **Authorization unavailable or source changed:** verify the intended recording ID and obtain genuine authorization and consent. If the source video changed, re-establish the attestation for the actual source and create a new reference-review session. Do not reuse stale approvals.
- **Report unavailable, mismatched or default-policy error:** verify both IDs and the backend/storage roots. Reconstruction requires the default server screening policy; do not lower thresholds to force a pass. If source frames or pose hashes changed, rerun the appropriate analysis on an authorized recording.
- **Missing session, ambiguous or missing subject, or review required:** resume the correct session ID or explicitly select a reference subject and review the frame. Inspect all candidate boxes, including suppressed ones. If identity or isolation remains uncertain, reject or recapture; a detector count does not prove one person.
- **Failed/unknown mandatory quality check:** exclude the frame or recapture with full body visible, adequate lighting and sharpness. Resolve the actual check rather than interpreting an unknown as a pass.
- **Multiple candidate centers or crop too small:** the reviewed box must contain the pose landmark extent and must not include more than one raw detector-candidate center; its pixel crop must be at least 32×32. Inspect the real frame, redraw only if it genuinely isolates the intended person and satisfies those rules, otherwise reject or recapture. NMS does not override the raw-box crop rule.
- **Image invalid or frame/hash changed:** do not reuse the approval. Check the frame and report provenance, rerun quality/pose analysis if needed, and perform a fresh review. If preflight lists image or crop validation as unevaluated, first supply its missing inputs.
- **Engine not ready, HTTP error or interrupted/failed run:** check the matching backend `/health`, CUDA/model load error and per-frame details in `status.json`. Do not treat a failed frame, interrupted run or browser viewer error as a successful mesh. Preserve the error separately and retry only after resolving it and repeating the required review/confirmation.
